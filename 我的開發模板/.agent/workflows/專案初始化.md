# 專案初始化流程

當你（AI Agent）首次接觸一個使用此模板建立的新專案時，請嚴格按照以下順序執行。

---

## 1. 閱讀專案規範

依序閱讀以下文件，建立對專案的完整理解：

1. `README.md` — 專案說明
2. `.cursor/rules/mainrule.mdc` — 全域開發規範
3. `.cursor/rules/projectrule.mdc` — 專案特定規範

> 若 `projectrule.mdc` 中仍有未填寫的 `TODO` 項目，提醒用戶填寫後再繼續。

## 2. 確認專案狀態

檢查以下檔案的狀態：

| 檔案 | 檢查項目 | 若未完成 |
|------|---------|---------|
| `需求/需求文檔.md` | 是否已有具體需求內容 | → 觸發 Skill「需求文檔撰寫」 |
| `需求/頁面結構/` | 是否已有頁面結構圖 | → 觸發 Skill「開發流程設計」 |
| `需求/流程圖/` | 是否已有功能流程圖 | → 觸發 Skill「開發流程設計」 |
| `.cursor/rules/projectrule.mdc` | TODO 項目是否都已填寫 | → 提醒用戶填寫 |
| `devlog/devlog.md` | 專案資訊是否已填寫 | → 填寫專案資訊區塊 |

## 3. 填寫專案資訊

若 `devlog/devlog.md` 的專案資訊尚未填寫：
1. 根據用戶提供的資訊，填寫專案名稱、時間、期限、技術棧
2. 使用 `tree` 或 `find` 指令產生實際目錄結構
3. 建立初步的開發規劃

## 4. 確認開發階段

向用戶確認當前專案處於哪個階段：

```
階段 1 — 需求確認    → 使用 Skill「需求文檔撰寫」
階段 2 — 設計規劃    → 使用 Skill「開發流程設計」
階段 3 — 開始開發    → 按需求文檔逐模塊開發
階段 4 — 測試驗收    → 使用 Skill「客戶測試流程」
```

## 5. 建立當日日誌

1. 確認當前時間（執行 `date` 指令）
2. 建立 `devlog/YYYY-MM-DD-devlog.md`
3. 記錄專案初始化完成的時間與初始狀態

---

> [!IMPORTANT]
> 初始化完成後，請向用戶報告專案狀態摘要，包括：
> - 哪些文件已就緒、哪些需要填寫
> - 建議的下一步動作
> - 任何需要用戶確認的問題
