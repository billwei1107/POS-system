## POS Expired Session Redirect Fix

- 時間：2026-05-16 19:08:32 CST。
- 問題：使用者隔一段時間再進入 POS，JWT 已過期時仍停留在主畫面，收銀台商品 API 失敗後顯示「商品載入失敗」，沒有回到 PIN 登入頁。
- 根因：
  - `ProtectedRoute` 只檢查 zustand 的 `isAuthenticated`，未檢查 JWT payload 的 `exp`。
  - `PosLoginPage` 若看到已持久化的 `isAuthenticated=true`，也會直接導回收銀台，即使 token 已過期。
  - Axios response interceptor 只處理 HTTP status `401`；若後端回 `ApiResponse { code: 401 }`，前端會把它正規化成一般失敗 response，讓頁面顯示商品載入錯誤。
- 前端修復：
  - `authStore` 新增 JWT payload 解碼與 `isTokenExpired()`，持久化 hydration 與 `setAuth()` 都會拒絕過期 token，並同步清除 `pos-session`。
  - `ProtectedRoute` 在 route render 時檢查 token 是否過期，過期時清除 auth/POS session 並導回登入頁。
  - `PosLoginPage` 遇到已過期的持久化登入狀態時先 logout，不再自動把使用者推回收銀台。
  - `axiosInstance` 將 HTTP 401 與 response body `code: 401` 都視為認證失效，集中 logout，避免頁面只顯示商品載入失敗。
- 測試：
  - 擴充 `authStore.test.ts` 覆蓋 JWT 到期判斷與拒收過期 token。
  - 新增 `ProtectedRoute.test.tsx` 覆蓋 POS route 遇到過期 JWT 時導回 `/pos/login` 並清除 `pos-session`。
  - 新增 `axiosInstance.test.ts` 覆蓋 API body `code: 401` 時集中登出。
