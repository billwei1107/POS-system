# 2026-05-15 Devlog

## Planning

- 進入 POS 後端正式化的 CRM 點數一致性階段。
- 目標：訂單完成付款後既有自動累點要保持不變；退款完成後要依退款金額自動回沖該筆訂單已發放點數，避免會員退款後仍保留點數。
- 回沖需具備冪等保護，避免同一筆退款重複完成或事件重播造成重複扣點。

- `backend/app/`
  - POS 後端啟動模組與本地 demo seed。

- `devlog/`

## Progress

- `RefundCompletedEvent` 新增 `memberId` 與 `completedRefundTotal`，保留舊建構子相容既有測試與事件使用者。
- `RefundService.completeRefund()` 完成退款後會統計同訂單已完成退款總額，並把會員 ID 與累計退款總額一併發布。
- `PointLedger` 新增 `referenceId`、`referenceType` 與 `REFUND_REVERSE` 原因。
- 新增 Flyway migration `V9002__add_pos_crm_point_ledger_references.sql`：
  - 點數流水新增 reference 欄位。
  - 既有 `ORDER_EARN` 流水以 `order_id` 回填 reference。
  - 將冪等唯一索引改為 `(reference_id, reason)`。
- `MemberService` 新增退款完成事件處理：
  - 同一 `refundId + REFUND_REVERSE` 已存在時直接略過。
  - 以該訂單原始 `ORDER_EARN` 點數作為上限。
  - 依 `completedRefundTotal / 10` 取整計算目標回沖點數。
  - 扣除同訂單既有回沖點數，只回沖本次差額，支援部分退款。
  - 回沖允許會員點數短暫為負，避免會員已使用點數後退款交易失敗。
- `PointLedgerResponse` 回傳 `referenceId` 與 `referenceType`，方便前端與 API 檢查流水來源。
- 補齊單元測試：
  - POS core 驗證退款完成事件包含會員與累計退款總額。
  - POS CRM 驗證全額退款回沖、第二次部分退款只回沖差額、重複退款事件不重複扣點。
