# POS 開發進度對照

> **更新時間**: 2026-05-11 03:13 CST
> **用途**: 作為 `開發流程規劃.md` 的執行狀態表。之後每次開發前先看本文件，確認目前 Sprint、完成度、MVP 與下一步。

## 目前策略

目前專案已不再是空白 bootstrap，已有多個 POS 模組與前端頁面。實際開發策略調整為：

1. 先補齊「咖啡廳 POS 可操作主流程」：登入 → 商品 → 購物車 → 折扣/會員 → 掛單 → 結帳 → 現金找零 → 訂單紀錄。
2. 已做成 MVP 的流程，後續再依 `開發流程規劃.md` 回補正式後端模組、資料表、測試與母體同步。
3. 每次繼續開發前，先確認本文件的「下一步建議」，避免偏離 Phase/Sprint 主線。

## 缺口與風險

| 類型 | 缺口 | 影響 |
|------|------|------|
| 測試 | 前端尚未建立 Vitest/RTL/MSW 基線 | shared 與 POS UI 邏輯目前主要靠 build + Playwright |
| 後端整合 | 尚未全量跑 `mvn verify` / Testcontainers | 跨模組事件、Flyway 全量相容性需補強 |
| 模組同步 | POS 內可復用修正尚未逐項同步回母體 | 模塊化組件正式導入其他專案前需整理 |
| 掛單 | 已可跨刷新由後端取回，但尚未補權限與過期策略 | 多終端併發取回、不同操作員權限、逾期掛單清理仍需設計 |
| 會員 | 目前不查後端會員資料 | 無真實會員建立、點數、儲值、消費歷史 |
| 支付/班次 | 現金支付已串 cash drawer 與每日 reconciliation；多支付方式與完整日結仍未全量驗證 | Checkpoint 6 需補前後端測試基線，降低後續改動回歸風險 |
| 稅務 | 已完成 mock invoice happy path；尚未建立正式字軌資料與真實 Turnkey 串接 | Phase 1 零售交付可先以 mock invoice 驗證，正式上線前需補字軌/財政部串接設定 |
| 庫存 | 已完成收銀扣庫與不足庫存攔截；尚未補盤點/調撥全流程回歸 | 正式導入前仍需補庫存異動查詢 UX、盤點與調撥驗證 |

## 下一步建議

1. **Sprint 1-3 payment transaction 已完成**
   - 結帳完成時建立 `pos_payment_transactions`。
   - 現金付款寫入 payment method、paid amount、tendered amount、change given。
   - 訂單列表可查該筆付款記錄。

2. **Sprint 1-4 tax happy path 已完成本次 checkpoint**
   - 訂單完成後自動建立 mock invoice。
   - 發票 `tax_amount` 與訂單 `tax_total` 一致。
   - 前端可在發票頁查到。

3. **Checkpoint 3 inventory 扣庫存端到端已完成**
   - 訂單完成後扣減對應商品庫存。
   - 庫存不足時不得完成付款，需回傳可理解錯誤。
   - 庫存頁或異動紀錄可看到扣減結果。

4. **Checkpoint 4 staff shift / cash drawer / reconciliation 已完成**
   - 建立或確認開班、收銀、關班、對帳流程。
   - 現金付款必須彙總到當班或 cash drawer。
   - 對帳頁能看到當班現金收入、訂單數、payment transaction 金額。

5. **Checkpoint 5 訂單查詢與退款閉環確認已完成**
   - 訂單列表需看到完成訂單、付款狀態與發票狀態。
   - 回歸 refund workflow，不得破壞既有退款功能。
   - 補缺漏文件或測試。

6. **下一步：Checkpoint 6 前端與後端測試基線**
   - Vitest/RTL/MSW。
   - `cartStore`、`moneyFormat`、`CheckoutPage` 關鍵邏輯測試。
   - 後端補核心 service/controller 測試：payment transaction、invoice、inventory、shift/reconciliation。

## 後續開發執行規則

- 每次「繼續開發」前，先讀本文件與 `開發流程規劃.md` 對照。
- 每次完成前端或使用者流程，必須重建 frontend 並用瀏覽器實測。
- 若某功能只是 MVP，必須在本文件標記，不視為正式 Sprint Done。
- 真正 Sprint Done 需同時滿足：後端 API、前端頁面、測試、Docker 驗證、devlog、必要時同步母體。
