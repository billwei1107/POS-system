# POS 功能檢驗流程書

本文件定義 POS 專案完成標準、測試案例與驗收流程。Codex 實作完成後必須依此驗證，並將結果記錄在 `devlog/YYYY-MM-DD-devlog.md`。

## 1. 驗收總則

- 每個 P0 功能必須有正常流程、異常流程與權限檢查。
- 涉及資料寫入的功能必須驗證 API 回應與資料庫結果。
- 涉及前端 UI 的功能必須執行 `npm run build`，並在瀏覽器實際操作驗證。
- 涉及後端邏輯的功能必須執行對應 Maven 測試，最小範圍為受影響 module。
- 涉及通用模塊修正時，需確認是否回寫 `/Users/wei/Desktop/code/模塊化組件/`。
- 驗證結果必須記錄在當日 devlog。

## 3. 標準測試流程

### 3.1 後端測試

```bash
cd backend
mvn clean verify
```

針對單一模組：

```bash
cd backend
mvn -pl module-pos-product -am test
```

### 3.2 前端測試

```bash
cd frontend-web
npm run build
npm run lint
```

若有 UI 或互動改動，需啟動前端並用瀏覽器實測：

```bash
cd frontend-web
npm run dev
```

### 3.3 Docker 測試

```bash
cd docker/local
docker compose up -d
curl http://localhost:38080/actuator/health
```

### 3.4 Reference 測試

```bash
bash scripts/setup-module-reference.sh
git -C reference/模塊化組件 describe --tags --exact-match
```

預期 tag：

```text
module-v2026.05.10.2
```

## 5. 邊界情境

| 編號 | 情境 | 輸入 | 預期結果 |
|------|------|------|----------|
| B-001 | 金額精度 | 小數金額、折扣、稅額、找零 | 使用 `BigDecimal` 計算，前後端顯示一致 |
| B-002 | 空值與必填 | 商品名稱、價格、門店、員工、支付方式缺失 | API 回傳欄位驗證錯誤，不寫入資料 |
| B-003 | 極端數量 | 大量商品明細、庫存異動、盤點資料 | API 不逾時，資料分頁與索引可支援 |
| B-004 | 重複請求 | 重複送出支付或退款 | 避免重複扣款、重複退款或重複庫存異動 |
| B-005 | 權限越界 | 收銀員操作主管功能 | 後端拒絕，前端不暴露不可用操作 |
| B-006 | 網路中斷 | WebSocket 斷線或 Redis 不可用 | 前端提示狀態，核心交易不被非核心通知阻塞 |

## 6. 回歸測試

| 編號 | 受影響功能 | 必測原因 | 驗證方式 |
|------|------------|----------|----------|
| R-001 | auth / organization | 多數模組依賴使用者、角色、員工、門店 | 登入、權限、員工門店查詢 |
| R-002 | module-common | 統一回應、安全工具、BaseEntity 影響全系統 | 後端全量 `mvn clean verify` |
| R-003 | pos-product / pos-core | 商品資料會影響訂單交易 | 商品 CRUD 後建立訂單 |
| R-004 | pos-payment / pos-tax | 支付和稅額會影響財務資料 | 建立支付、發票、退款 |
| R-005 | frontend shared | 共用元件、hook、theme 影響多頁面 | `npm run build` + 主要頁面瀏覽器操作 |
| R-006 | reference / module sync | 通用能力可能需回寫母體 | 檢查母體路徑、reference tag、devlog |
