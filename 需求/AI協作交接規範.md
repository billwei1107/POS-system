# AI 協作交接規範

本文件定義 Claude 與 Codex 在 POS 專案中的分工。目標是讓 Claude 先把需求與驗收標準整理清楚，再由 Codex 依專案實際架構落地實作。

## 1. Claude 階段：規劃與規格

Claude 應補齊以下文件：

```text
需求/需求文檔.md
需求/系統規格表.md
需求/開發流程規劃.md
需求/功能檢驗流程書.md
```

Claude 可以產出：

- 使用者角色與權限需求
- 功能範圍、優先級、業務規則
- 系統技術棧、架構與部署需求
- 模塊化組件選型建議
- API 需求與資料需求草案
- 頁面清單、資訊架構與使用者流程
- 驗收標準、測試案例、錯誤案例、邊界案例
- 待確認問題與風險

Claude 不應產出：

- 指定某個檔案第幾行要怎麼改
- 強制指定函式名稱、class 名稱、CSS class 名稱
- 強制指定 migration 版本號、索引名稱或低階實作細節
- 未經需求證明就指定特定第三方套件
- 把開發步驟拆成過細的施工指令

## 2. Codex 階段：實作與驗證

Codex 接手時應閱讀：

```text
AGENTS.md
ai-project-start.md
需求/README.md
需求/AI協作交接規範.md
需求/需求文檔.md
需求/系統規格表.md
需求/開發流程規劃.md
需求/功能檢驗流程書.md
reference/模塊化組件/ai-handoff.md
```

Codex 應負責：

- 檢查 Claude 規劃是否可執行
- 確認或初始化 `reference/模塊化組件`
- 根據需求自行決定實作細節
- 使用 `module-export.sh` 導入需要的模塊
- 實作後端、前端、資料庫與部署配置
- 執行測試與功能檢驗
- 更新 `devlog/` 與 `troubleshooting.md`
- 若發現通用模塊 bug，依 `reference/模塊化組件/ai-handoff.md` 回寫母體

## 3. 交接完成條件

Claude 交接給 Codex 前，至少應完成：

- `需求/需求文檔.md` 無主要未定項
- `需求/系統規格表.md` 已列出技術棧與環境需求
- `需求/開發流程規劃.md` 已列出階段、模塊、依賴與風險
- `需求/功能檢驗流程書.md` 已列出驗收與測試案例
- 未確認問題集中列於各文件的「待確認問題」區塊

若以上文件缺漏，Codex 應先要求補齊或在接手前列出缺口。
