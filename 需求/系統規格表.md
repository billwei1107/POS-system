## 7. Flyway 與資料規格

Flyway locations 由 `backend/app/src/main/resources/application.yml` 設定，目前包含：

```text
db/migration
db/migration/organization
db/migration/workflow
db/migration/notification
db/migration/attendance
db/migration/leave
db/migration/pos/product
db/migration/pos/core
db/migration/pos/payment
db/migration/pos/tax
db/migration/pos/inventory
db/migration/pos/staff
```

資料規格原則：

- 商業資料表應具備 `id`、`created_at`、`updated_at`。
- 重要商業資料使用 `deleted_at` 軟刪除。
- 金額欄位後端使用 `BigDecimal`，不得使用 `double`。
- 跨模組關聯以 ID 與 service/event 溝通，避免跨模組直接操作 repository。

## 8. 安全規格

| 項目 | 規格 |
|------|------|
| 認證 | JWT |
| 權限 | RBAC |
| POS 終端 | PIN login、quick switch、terminal monitor |
| 密碼與 PIN | 不得明碼儲存，需使用雜湊 |
| 機密 | 不提交 `.env`、token、API key、真實密碼 |
| 日誌 | 不輸出密碼、信用卡、身分證字號等敏感資料 |
| SQL | 使用 ORM / Prepared Statement，不組字串 SQL |

## 9. 非功能規格

| 類別 | 規格 |
|------|------|
| 可維護性 | 後端以 module 分層，前端以 `shared/` 與 `features/` 分層 |
| 可移植性 | 通用能力回寫母體，POS 客製能力留在 POS 專案 |
| 可驗證性 | 後端跑 `mvn clean verify`，前端跑 `npm run build` |
| 可部署性 | 本地 Docker Compose 四服務可啟動 |
| 可擴充性 | 透過 `modules.*` 與 `pos.features.*` 切換業態能力 |
| 可追蹤性 | 每次開發更新 `devlog/YYYY-MM-DD-devlog.md` |
